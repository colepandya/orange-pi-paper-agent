# Build 41  (strategy S6): the Financial Reasoning Engine, graph visibility, leftover clean-up
* **The bot's own Financial Reasoning Engine replaces the LLM** (docs/REASONING_ENGINE.md). Rules and data only: no language model, no key, no network, no cost. It is the DEFAULT analyst and red team (Settings -> System -> Reasoning engine: rules / llm). The old LLM code is kept, untouched, and runs only if you choose engine=llm.
  * ANALYST: reads each news item and returns exactly what the LLM analyst returned (event, certainty, who benefits and who loses by causal order, chain, themes, bull/bear case, supporting quotes, contradictions), plus the rules that produced it. It tells a confirmed event from a plan, an unconfirmed rumour and a denial; works out who is the acquirer and target or plaintiff and defendant; follows the relationship graph two hops with decay; applies macro exposures (oil, gold, copper, uranium, rates, chip export curbs, conflict); flags contradictions (headline vs body, good and bad facts together); and ABSTAINS when the evidence is thin.
  * RED TEAM: before every trade it builds the strongest case against it (already priced in, contradicting news, rumour or denial, stale news, crowded theme, stop inside a normal day's move, thin edge, thin volume, hostile regime) with severities, a fatal-flaw test and tripwires (a price level and the events that would prove the idea wrong, for shorts too); the existing deterministic gate decides.
  * QUESTIONS: `python3 -m paper_agent ask "why NVDA"` and an Ask box on the Intelligence tab: why / news / related / what if <stock> <event> / compare / theme / what could hurt us / today / help. It answers from the bot's own data and says so when it cannot answer.
  * Its reliability is learned per hop and event type from outcomes, kept apart from the LLM's (source RULES-analyst).
* **The relationship graph is now visible**: Intelligence tab -> Relationship graph (what is in it, when it was loaded and refreshed, any stock's neighbours, what each kind of event would do to them, every idea it has produced); `python3 -m paper_agent graph NVDA`.
* **Leftover clean-up** (`sudo bash scripts/cleanup-legacy.sh`, dry run by default): the legacy v4 tables and decisions (db-maintain), old re-forecasts, stale caches and logs, the old v4 app folder in /opt/paper-agent, stale unit copies, old install backups, old unpacked builds and zips in the home folder, old temp files, and dead v4 keys in config.json. Archives first, allow-list only, verifies the effective configuration is unchanged. On a copy of the owner's database: 31.9 MB -> 20.5 MB.
* Shorts' tripwires: price-above and good-news tripwires for short positions.
* Tested with the old LLM paths pinned: with every new feature off the bot is identical to build 38 (6 scenarios).
